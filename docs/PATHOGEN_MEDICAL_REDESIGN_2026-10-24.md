# Gugu-Gaga: Outbreak & Care — 病原体与医疗重设计（实验草案）

**目标版本：** Minecraft 1.21.1 / NeoForge 21.1.x / Java 21

**与原项目的关系：** 本分支从旧 v0.10 H 键界面源码派生，但不修改 `main`、已冻结 PR #29–#31，亦不覆盖《山海经》/《聊斋》独立 PR #32。原三种角色、贴图与恐怖事件保留为遗产内容，将来可以作为可关闭的背景事件；本方向的主体不是惊吓，而是**可理解的疾病调查、保护与救治循环**。

## 核心玩法

**调查 → 防护 → 接触事件 → 症状观察 → 检测 → 分类医疗 → 康复。** 过程围绕玩家做选择，而不是靠命令行或随机无征兆削血。流行病学的词汇可以来自真实教育资料，但**所有会决定传播、病程或治疗效果的数值都是原创游戏平衡参数，不对应现实生物学参数**。

1. **不同类别：** 病毒和细菌分开建模，绝不使用“抗菌药品立刻治好任何病毒”之类的错误规则。游戏内测试用 `mist_fever`（虚构病毒）与 `rust_bloom`（虚构细菌）仅为占位案例，不包含真实病原体的繁育、传播条件或实验制作方法。
2. **不同接触：** “飞沫事件、血液接触事件、共用物品事件”是明确的 **Minecraft 游戏事件类型**。它们不是现实传播途径的定量模型。任何普通攻击、附近站立、经过玩家身边或者直接扫描其他生物，都不能自动触发血液接触感染。只有确认的游戏事件，而且玩家已经自愿参与、在生存模式、未开启安静模式，才进入感染状态。
3. **防护与公共卫生：** 手套、遮挡面部的装备、完整防护套件、隔离房间、清洁站及告示牌。装备有可读描述和明确的游戏内效果；它们 **不是** 对现实保护效果的评价，更不代表穿戴防护即零现实风险。
4. **症状与状态：** `CLEAR → LATENT → SYMPTOMATIC → RECOVERING → RECOVERED`。计时完全以游戏 tick 为单位，不能据此推断真实病原体潜伏期、传染期或治愈率。图形表现使用非血腥的状态标签、轻度音画提示与 HUD；玩家可关闭闪烁、特殊音效和恐怖特效。
5. **医疗决策：** 测试包揭示 **游戏内**病毒/细菌分类。支持性护理可以改善游戏状态但不会立即消灭病因；针对性抗菌物品仅适用于**已检测、设定允许响应**的虚构细菌状态，不治疗虚构病毒。可以设置需要延长照护或无法响应针对性护理的虚构状态，而不是“一瓶万能药”。
6. **医疗设施：** 原创工作台 / 基础检查台、病历簿、标记牌、防护柜、观察床、康复区。院内工作应有清楚的 UI 反馈。优先加入 **H 键可重映射界面**，例如“检查状态 / 使用测试包 / 防护 / 隔离 / 治疗”，普通玩家不应必须输入斜杠命令。
7. **教育图鉴：** 可以引用 CDC、WHO 的公开**高层级科普**，解释病毒和细菌的差别、为什么抗生素不能治疗病毒、合理防护和医疗判断。不要包含现实病原体的培养、改造、传播优化、采样操作、诊疗剂量或实验性制剂内容。

## 技术架构

- `pathogen/PathogenGamePolicy.java` — 第一轮已提交的纯 Java21、不可变、有限状态引擎；内置两种**虚构**情景，定义接触、防护、病程和分类护理。它没有 NeoForge 事件监听器、游戏物品、玩家 NBT 存档、GUI 或自动感染功能，因此目前**不能宣称在 Minecraft 中已经能感染/治疗**。
- `qa/java/PathogenGamePolicySmoke.java` — 循环所有事件类型、保护装备、显式确认、玩家同意、生存/安静/启用状态，验证不发生意外接触与虚构状态的闭环进展。
- `.github/workflows/build.yml` — 在现有 NeoForge build、服务器/客户端启动 CI 前增加独立 Java21 引擎测试。
- 下一步的**真实游戏竖切**：1 个实验 NPC + 2 个工作台/医疗物品 + 1 个可重映射玩家 H 界面页；在玩家主动交互后才触发服务器侧的 `VerifiedEvent`，并使用官方 NeoForge typed networking 持久化本人状态，避免客户端伪造感染/医疗结果。
- 性能限制：只更新参与者自己已经加载的状态；有事件上限、玩家人数上限和固定 tick 预算。不为传播扫描未加载区块、不扩增世界生成负担、不添加常驻渲染粒子或跨维度强制加载。
- 多人模式：严格按用户/玩家隔离数据，不共享敏感真实健康资料；可随时退出，能保留世界结构。没有 Web 请求或现实医疗记录上传。
